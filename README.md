**Educational simulation of keyed statistical text watermarking.** This project does not
reproduce Anthropic's Claude watermarking implementation, its keys, its detector, or its
probability distributions. It uses a local, open-weight model (Qwen) to obtain real
next-token probabilities, then applies a simplified, self-contained keyed reweighting scheme
built entirely for this demo to illustrate the statistical idea behind watermarking.

## Why this matters

An oil & gas professional does not need to know how text watermarking works to drill a well,
design a completion, or run a CT intervention. The value is in understanding what happens
when generative AI starts producing engineering documentation — daily drilling and completion
reports, end-of-well reports, well intervention summaries, NPT descriptions, lessons learned,
risk assessments, tender responses, and RAG-generated answers from knowledge-management
systems are all places LLM-generated text can already end up.

Once a paragraph like *"Summarise the causes of NPT during the 8½-inch section"* gets copied
into a report, provenance questions follow: was this written by an engineer, generated by an
AI, or generated and then reviewed? Can an organisation detect AI-generated material later?
That's where watermarking becomes relevant — and this project builds up to it from a simpler,
more fundamental idea: LLM output is probabilistic, not retrieved from a database, and
watermarking changes *how a model samples from that probability distribution*, not the
underlying engineering knowledge.

## Purpose

Statistical text watermarking works by nudging an LLM's token-sampling choices with a secret
key, so that a detector who knows the key can later tell, statistically, whether a piece of
text was likely to have come from that model. This project makes that idea concrete using
oil & gas drilling/completions language:

1. Extract **real** next-token probabilities from Qwen for a set of oil & gas prompts (Python).
2. Import those real probabilities into Mathematica and simulate a keyed watermark reweighting,
   normal vs. watermarked sampling, and statistical detection experiments (Wolfram Language).

## Architecture

```
Oil & gas prompt → Qwen → logits → softmax → JSON → Mathematica →
simulated keyed sampling → statistical detection experiment
```

## Requirements

- Python 3.11+
- torch, transformers, accelerate, pandas, numpy, matplotlib, pytest (see `requirements.txt`)
- Mathematica 14.x (preferred) to open `notebooks/02_oil_gas_text_watermarking.nb`

## Setup

1. Create and activate a virtual environment:
   ```
   python3.11 -m venv .venv
   source .venv/bin/activate
   ```
2. Install dependencies:
   ```
   pip install -r requirements.txt
   ```
3. Run the tests (no model download required):
   ```
   pytest tests/
   ```
4. Open and run `notebooks/01_extract_next_token_probabilities.ipynb` top to bottom. This
   downloads `Qwen/Qwen2.5-1.5B-Instruct` on first run, extracts real next-token probabilities
   for 12 oil & gas / comparison prompts, generates one real 8-step continuation via genuine
   greedy decoding, and writes `data/processed/next_token_distributions.json`.
5. Open `notebooks/02_oil_gas_text_watermarking.nb` in Mathematica and evaluate the notebook
   from the top. It imports the JSON from step 4 and runs the simulated watermarking
   demonstrations interactively.

The Mathematica notebook has two layers:
- **Setup + Presentation Mode** (open by default): why this matters for an oil & gas audience
  and where LLM-generated text already shows up, "What You Are Seeing" and a glossary, a
  pipeline diagram, one real Qwen token decision explained candidate-by-candidate (real
  probability, key score, and watermarked probability side by side for every candidate), a
  table replaying 8 real consecutive decision points from one actual Qwen continuation (never
  a rewritten sentence — watermarking biases one sampling decision at a time, it doesn't edit
  finished text), a real comparison of how much less "room" a watermark has in constrained
  technical language (e.g. "5,000 psi for 15 ___") versus generic text, common
  misconceptions, and a plain-language score interpretation.
- **Technical Mode** (collapsed by default — click the section header to expand): the full
  interactive machinery — prompt/probability exploration, context and strength sensitivity,
  statistical signal accumulation, a Monte Carlo experiment, an optional z-score detector, a
  worked example pulled dynamically from the real data, limitations, and reproducibility.

## Disclaimer

This project is an educational simulator. It does not reproduce Anthropic's Claude
